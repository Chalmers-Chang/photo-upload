# web

## GOTCHA

- Slideshow `img { max-height: 100% }` does not shrink high-res JPEGs when the frame has no definite height; the photo paints at intrinsic size. Pin the frame with `minmax(0, 1fr)` and position the image with `max-width/max-height: 100%` so it letterboxes and stays centered.
- Do not sweep photos or rebuild `slideshow_q` on every `/api/slideshow` poll. Rebuild on upload, drop, and settings save. Poll only runs the Lua playhead; if the queue is empty but photos exist (first request after deploy), rebuild once.
- `.empty { display: grid }` overrides the `hidden` attribute, so 「尚無照片」 stays on top of real photos. Force `img[hidden], .empty[hidden] { display: none !important }`.
- Slideshow crossfade uses two stacked imgs and `opacity`; do not set `hidden` on them during the transition or `display: none` skips the fade.
- Lottery winner `overflow: hidden` clips the photo shadow into a hard straight edge when the JPEG fills the wrap. Keep the wrap `overflow: visible`. Use `box-shadow` (follows `border-radius`); `filter: drop-shadow` on a JPEG ignores radius and looks square. The 2cm result padding is the room for the blur.
- `Image.save(..., optimize=True)` on phone photos makes upload feel stuck (CPU Huffman pass). Save JPEG at quality 80 with no optimize; `draft()` + bilinear thumbnail for speed.
- Project-home glass looks gray on the first visit because `backdrop-filter` paints before the cover JPEG is decoded (Safari samples an empty layer). Keep a solid frost until `img.decode()`, then add `.is-ready` and turn blur on.
- Slideshow `img { opacity: 0 }` also hides the wall-mode background `<picture>` img. Scope slide rules to `.frame img`.
- Huge uploads look frozen because Pillow `convert("RGB")` materializes the full pixel buffer (HEIC/PNG skip JPEG `draft()`). Shrink in the browser to `JPEG_MAX_EDGE` before XHR, then `thumbnail(..., reducing_gap=2)` before convert. Admin asset `form.submit()` had no pie; use the same XHR overlay as guest upload. Pin the veil on `document.body` at z-index 1000 and paint a frame before shrink. Do not set `.progress-veil { display: grid }` unscoped: it overrides HTML `hidden` and the pie stays up, blocking clicks. Show only with `.is-on`. Overlay CSS lives in `_progress_veil.html` (not `style.css`) so a cached stylesheet cannot hide it. Keep the overlay at least 700ms before reload. After a successful asset POST, `sessionStorage.adminOpenProject` re-opens that project `<details>`.

## TASTE

- Admin project card is a closed `<details>` by default; summary shows a name link to project home plus a small open-project icon, and copy/QR icons per URL (project, upload, slideshow). 「刪除專案」 is left-aligned after 「更多」 expands. QR opens a dialog with project name, PNG, and download (`/admin/projects/<id>/qr/<kind>.png`). Asset upload is a single 「上傳」 control: the file picker opens on click and `onchange` submits the form. 「刪除專案」 is ~70% of the old danger button; click reveals in-page 「確認」/「取消」 (no `window.confirm`). Confirm removes Redis, photo files, project record, and slug URLs (`/p/<slug>/` 404). Bottom-left settings sit in the same 2-col grid as asset cards (one cell wide, left). They store per-project `slideshow_mode` (`wall` or `full`, one at a time), `slideshow_interval`, `slideshow_fade`, `slideshow_queue_max`, `slideshow_per_device`, `lottery_sphere_max`, `lottery_seconds` on the Redis project hash; create copies defaults from `config/appsetting.py`. Interval/fade/queue knobs are shared; only the slideshow layout changes. `wall` is the message-wall (name + caption). `full` is photo-only on cream `#f4efe6`, no background overlay, no 2cm pad, no name/note. `slideshow_fade` is seconds (0–3, default 0.8; 0 = hard cut).

- Fit photos inside the viewport (`object-fit: contain`). Do not set `width/height: 100%` or small photos get stretched.
- Viewport split is repo-wide: Mobile `max-width: 640px` and Desktop `min-width: 641px`. Size knobs live in those two blocks (`--pjt-*` on home, `--glass` on upload/admin/login). Admin asset grid also stacks at 640px. When the user asks to resize UI, ask 手機 or 桌機 first. Cover photos use `<picture>` (`project_home`, `_stage_bg.html` on slideshow/lottery) so only the matching JPEG downloads. Desktop 「開始分享」 lead is 22px; mobile stays 16px.
- Admin and Back use the stage-card glass (frost fill + `rgba(255,255,255,0.55)` border) and the home 「輪播照片」 type (bold faded ink, `BUTTON_TEXT_FADE`). Size stays `8px 14px` / 14px. Positions are owned by `_admin_chrome.html`: `top: 12px`, inset `--chrome-inset` (`GLASS_PAD_MOBILE_CM` / `GLASS_PAD_CM`) so every page matches. Logout on the admin list keeps 44px height. 「登出」 is only on the admin list page, above `@ChalmersProduction`, same cream/white/ink pill as Admin, min-height 44px and `appearance: none` so iOS does not squash the label. The project-name open icon is 16px (half of the URL copy/QR buttons). `@ChalmersProduction` is a fixed footer watermark on every page except slideshow (`_credit.html` in `base.html` and `lottery.html`). Slideshow, upload, and lottery use the same pill 「返回 / Back」 top-left to project home (slideshow also honors Escape). On slideshow, Back and Admin fade out after 5s of no mouse movement and return on move (stay visible while the cursor is on them). Bilingual `msg.py` newlines need `white-space: pre-line` (and `|tojson` for JS strings); HTML attributes collapse `\n`. Session cookie is permanent 30 days; `/admin` skips the login form when `session["admin"]` is set.
- Guest upload accepts up to 5 files per submit (`multiple`); admin asset 「上傳」 uses the same overlay (`_progress_veil.html` + `upload_progress.js`). XHR shows a home-style glass overlay inset 2cm with a gold pie + percent (bytes on `xhr.upload`, then 「處理照片中」 until the JSON reply). Oversized files are resized in the browser to `JPEG_MAX_EDGE` (2560) JPEG before send (`pjt-mark` stays PNG). Each saved JPEG adds one lottery ticket. One caption applies to the batch. After `LOTTERY_CHANCE_MAX` (default 10) the flash switches from 「+1」 to the cap copy (keep uploading; slideshow/lottery use latest 10). Lottery uses each device's newest 10 photos; older tickets rotate off. Slideshow queue is `slideshow_q` (max `SLIDESHOW_QUEUE_MAX`, default 100). If total photos exceed that, keep each device's newest `SLIDESHOW_PER_DEVICE` (default 5) then the newest 100. Lottery is admin-only. After a draw, that device is added to `lottery_won:{project_id}` and skipped on later draws and the sphere (the winning spin still includes them). Lottery page bottom-left 「重置抽獎」 (white bold) only deletes that set; tickets and photos stay. Sphere keeps at least 30 photos (pad by repeat). Spin angular speed is exponential decay via rAF (`ω ∝ e^{-kt}`). Winner photo pop and sparkle burst start ~0.5s before the spin duration ends. Winner uses slideshow contain-and-center, inset `LOTTERY_PAD_CM` (default 2cm) from the screen. After the draw, the sides show that device's newest 10 minus the winning photo (max 5 thumbs per side). The congratulations count is the device's total uploads. Click a thumb to preview, centered on the winner photo; the rest of the screen dims ~82%. Click again to close. Sparkles mix pale gold 50%, silver 30%, cream 20%: 2000 dots while the sphere spins, using the same exponential rotateY/X as the sphere; radius grows with that ease and dots spawn across the spin. Size is ~2× prior, alpha ≈ 0.2. Trails use canvas fade (`destination-out`) plus a short stroke from the previous point. On win they split to 5000 and burst in the same beat as the winner photo pop (`k=3.2`, ~0.85s), then ease onto a jittered full-screen grid and bob vertically within 0.5cm at staggered slow frequencies. rAF stops on reset or hidden tab. After the draw, top-left Back goes to project home; bottom 「再抽一位」 resets the stage and draws again.
- First visit with no `device_name:{id}` shows a nickname modal (`/api/profile`). Slideshow and lottery labels use that name via the photo's `device_id`.
- Favicon is `web/static/favicon.png`, linked from `_favicon.html` (base, slideshow, lottery). To swap, overwrite that PNG; source zip lives in `art/favicon/`.
- User-facing copy lives in `config/msg.py` as bilingual `中文 / English` strings. Templates get `msg` from the Flask context processor. Upload page copy is Chinese then English, left-aligned (`pre-line` on title, labels, flash, notice). The upload button label stays centered. Textarea placeholder uses `&#10;` so the newline survives the HTML attribute.
- Blank project slug = lowercase `project_name` with symbols/spaces stripped (`a-z0-9` only). Empty result (e.g. Chinese-only name) falls back to a short hex id.
- Project folder holds optional desktop/mobile pairs: `pjt-desktop.jpg`, `pjt-mobile.jpg`, `bkg-desktop.jpg`, `bkg-mobile.jpg`, `lot-desktop.jpg`, `lot-mobile.jpg`, plus `-sm.jpg` thumbs, and `pjt-mark.png` (home mark between title and lead, same Admin upload control; PNG so transparency stays). Missing side falls back to the other, then legacy `pjt-home.jpg` / `bkg-slideshow.jpg` (lottery has no legacy file). Viewport ≤640px uses mobile. Full project delete `rmtree`s the folder. Slideshow photo in `wall` mode has ~22px Apple-style corners and 2cm inset from the screen. Name glass is above the photo, note glass below; both use project-home frost, bold faded ink (`rgba(28,25,21,0.48)`). Notes wrap every 30 characters. `full` mode is contain-and-center with cream letterbox, no glasses. Off-span `height: 0` so a long previous note cannot size the glass or shove the next photo. Stage column is `minmax(0, 1fr)`. Lottery uses the same `BKG_FADE` white overlay as slideshow.
- Project home, upload, and admin (list + login) use a full-viewport stage plus one home-style glass inset `GLASS_PAD_CM` (2cm, 1cm on phones). Title/form sit in a centered `glass-body`; `@ChalmersProduction` sits 0.1cm below the glass (lottery: 0.1cm below the 2cm inset). Admin list scrolls inside the glass so the credit stays put. Do not rely on `/static/style.css` for project-home layout. Pin `.admin-btn` to `position:fixed; z-index:30` on those pages.
- Per-project logs go to `LOG_DIR` (`/logs` in the container, `$HOST_PHOTO_DIR/logs` on the host): `<project-id>_yyyyMMdd.log`. Purge uses the date in the filename (not mtime) after 30 days. Skip `/health` and slideshow polls. 4xx/5xx and caught exceptions append `ERROR …` on the same line; unhandled exceptions set 500 and log `Type: message`. Errors with no project go to `app_yyyyMMdd.log`. If the directory is missing, skip the write; do not fail the request.
- Home/slideshow look knobs live in `config/appsetting.py` (and matching env): `PJT_FADE`, `BKG_FADE`, `TITLE_FADE`, `BUTTON_FADE`, `BUTTON_TEXT_FADE` are 0–1 (0 = original, 1 = gone/white). Button fills: `UPLOAD_BTN_COLOR`, `SLIDESHOW_BTN_COLOR`, `LOTTERY_BTN_COLOR`. Glass padding: `GLASS_PAD_CM` (desktop) and `GLASS_PAD_MOBILE_CM` (≤640px). Upload page edge inset: `UPLOAD_PAD_CM`. Lottery winner inset: `LOTTERY_PAD_CM` (default 2). Templates read them via `cfg`.
